# Длинные нарды

Настольная игра в браузере: доска рисуется на canvas, шашки и кости — обычные
элементы страницы, поэтому ходы плавно анимируются. Соперник — компьютер с тремя
уровнями, второй игрок за тем же экраном или человек на другом устройстве.

Играть можно здесь: **https://kutuzovilya.github.io/nardy/**

## Запуск

Открыть `index.html` в браузере. Ничего собирать не нужно, зависимостей нет.
Локально удобнее через сервер — иначе не работает игра по сети:

```bash
python3 -m http.server 8765
```

Одностраничная версия (все стили и скрипты внутри одного файла) собирается так:

```bash
node build.js
```

Результат — `dist/nardy.html`, его можно просто переслать или положить на любой хостинг.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `js/engine.js` | правила: ходы, голова, правило шести, выход шашек |
| `js/ai.js` | оценка позиции и выбор хода компьютером |
| `js/board.js` | геометрия доски и её отрисовка на canvas |
| `js/net.js` | сетевой стол: два транспорта, посадка, обмен состоянием |
| `js/banter.js` | реплики комментатора |
| `js/mock-db.js` | заглушка хранилища для отладки сети, в сборку не попадает |
| `js/ui.js` | ходы игрока, кости, журнал, диалоги, звук |
| `css/style.css` | оформление, светлая и тёмная темы |

Доска внутри — кольцо из 24 пунктов. Оба игрока идут в сторону возрастания
индекса: голова белых на пункте 0, голова чёрных на 12, дома — 18–23 и 6–11
соответственно. Такая система координат делает правила симметричными: позиция
шашки считается как `(пункт − голова) mod 24`.

## Реализованные правила

* с головы за ход снимается одна шашка; на первом ходу при 6-6, 4-4 и 3-3 — две;
* занять можно только свободный или свой пункт, шашки не бьются;
* разыгрывается максимально возможное число костей, при выборе одной — старшая;
* нельзя построить шесть своих пунктов подряд, заперев все 15 шашек соперника;
* выход из дома: точная кость снимает шашку с её пункта, большая — только с самой дальней;
* победа без единой снятой шашки у соперника считается марсом и даёт два очка.

## Игра по сети

Один создаёт стол и получает код из шести знаков и ссылку-приглашение; второй
открывает ссылку — и сразу садится напротив. Партия не пропадает при закрытии
вкладки: при следующем открытии игра возвращает вас за тот же стол.

Состояние партии всегда передаётся целиком, одним куском: позиция, кости,
журнал, счёт, кто на каком месте. Переписывает его только тот, чья очередь
ходить, поэтому рассинхронизации взяться неоткуда, а у каждой записи есть
растущий номер `seq` — копия, пришедшая с опозданием, отбрасывается.
Пришедшую позицию клиент не перерисовывает целиком, а сравнивает со своей и
двигает только сдвинувшиеся шашки: соперник видит нормальный ход, а не
мгновенную перестановку доски.

Транспорта два, выбирается сам:

* **Ретранслятор** — по умолчанию, в том числе на GitHub Pages. Состояние
  летит обычным сообщением в тему `nardy-<код>` на бесплатном
  [ntfy.sh](https://ntfy.sh), подписка идёт через SSE. Ни регистрации, ни
  ключей; сообщения живут 12 часов. Тема публичная, так что код стола — это
  и есть весь секрет.
* **Хранилище страницы** — если игра открыта как опубликованный артефакт
  Claude: там есть общий `db` с живой подпиской, список открытых столов и
  атомарная посадка, но доступ только внутри организации владельца.

Локально сеть можно погонять и без интернета: `index.html?mock=1` подменяет
хранилище заглушкой на `localStorage` + `BroadcastChannel`, и две вкладки
одного браузера играют друг с другом.

## Комментатор

За столом кто-то невидимый комментирует броски: шеш-беш, безнадёжные два-один,
пропуск хода, снятые шашки, марс. Реплики лежат в [js/banter.js](js/banter.js),
режимы — «как за столом» (с матом, по умолчанию), «прилично» и «тихо»,
переключается в настройках партии.

## Мелочи

* незаконченная партия и счёт матча сохраняются в браузере;
* «Подсказка» показывает ход, который выбрал бы компьютер на уровне «Мастер»;
* «Отменить» возвращает шашки в пределах текущего хода (⌘Z / Ctrl+Z);
* на телефоне в портретной ориентации доска разворачивается на 90°;
* адреса файлов помечены `?v=N` — после правок стоит увеличить номер в `index.html`,
  иначе браузеры будут держать старую версию.
